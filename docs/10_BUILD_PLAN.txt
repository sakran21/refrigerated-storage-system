1. PURPOSE
   ==================================================

This document defines the implementation plan for the Refrigerated Storage Unit Rental System.

This document defines:

* build strategy
* implementation phases
* vertical slice order
* backend/frontend/database sequencing
* testing checkpoints
* deployment checkpoints
* completion criteria for each phase

==================================================
2. BUILD STRATEGY
=================

The project will be built using vertical slices.

A vertical slice means one workflow is implemented across:

* database
* backend API
* business logic
* frontend UI
* validation
* role access
* notes behavior where applicable
* tests where applicable

The project will not be built as one large backend phase followed by one large frontend phase.

Each completed slice must produce usable application behavior.

==================================================
3. IMPLEMENTATION PRINCIPLES
============================

BP-001
Each phase must produce working software behavior.

BP-002
Database schema, backend API, and frontend UI must remain aligned.

BP-003
Business rules must be implemented in backend logic, not only in frontend validation.

BP-004
Frontend validation may improve user experience but must not replace backend validation.

BP-005
Locked records must be enforced by backend logic.

BP-006
Role restrictions must be enforced by backend authorization.

BP-007
Financial and historical records must not be silently deleted.

BP-008
Preview workflows must not save draft records.

BP-009
Submission workflows must require confirmation where specified.

BP-010
Demo seed data must use fake records only.

BP-011
Production secrets must never be committed to GitHub.
