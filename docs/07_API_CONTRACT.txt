==================================================
1. PURPOSE
==================================================

This document defines the backend API contract for the Refrigerated Storage Unit Rental System.

This document defines:
- API modules
- endpoint paths
- HTTP methods
- endpoint purpose
- role access
- request data
- response data
- validation rules
- business effects

This API contract guides the ASP.NET Core Web API implementation.

==================================================
2. API DESIGN PRINCIPLES
==================================================

API-001
The API must support real business workflows, not only raw CRUD operations.

API-002
Operator endpoints must support daily business use without exposing privileged correction or oversight tools.

API-003
Admin endpoints must support oversight, settings, review flags, audit review, financial review, and correction workflows.

API-004
Dev can access all endpoints for technical maintenance, debugging, deployment support, and emergency repair.

API-005
Dev access is not normal business workflow.

API-006
Financial records must not be silently edited, deleted, reversed, or overwritten.

API-007
Preview endpoints validate and return calculated preview data only.

API-008
Preview endpoints must not save draft records.

API-009
Submission endpoints require explicit confirmation where business mistakes are costly.

API-010
Sensitive actions must create audit logs and review flags where required.

API-011
Normal note creation does not create an audit log.

API-012
Admin note hiding and note restoring must create audit logs.

API-013
List endpoints must support pagination.

API-014
Major list endpoints must support filters.

API-015
The API must support tablet-first frontend workflows.

==================================================
3. AUTHENTICATION
==================================================

Authentication approach:
- ASP.NET Core cookie-based authentication
- Persistent browser sessions
- Role-based access control

Supported roles:
- operator
- admin
- dev

Rules:
- Inactive accounts cannot log in.
- Role determines business access.
- Dev has full technical access.
- Operator cannot access audit logs, review flags, Admin corrections, system settings, or oversight financial reports.
- Admin can access oversight and correction workflows.
- Persistent sessions remain active until logout, expiration, or invalidation.
